# 🤠 Ковбойская дуэль: Telegram-бот на HTML-виджетах (Bot API 10.4)

Прототип. Игра на реакцию: на экране виджета «Приготовься…», через случайные 2–6 секунд экран краснеет,
и побеждает тот, кто нажмёт первым. Нажал раньше сигнала — фальстарт и поражение.

* Python 3.12+, aiogram 3.x, SQLite (aiosqlite), long polling.
* aiogram 3.31 знает только Bot API 10.3, поэтому методы виджетов (`sendWidget`, `sendSharedWidget`,
  `answerWidgetQuery`, `editMessageWidgetData`, `editSharedWidgetData`) вызываются через тонкую обёртку
  `duelbot/bot_api_raw.py`, а апдейты `widget_query` / `shared_widget_query` перехватывает `DuelDispatcher`.
* **Режим по умолчанию — «на интерес».** Ставки в Stars и TON реализованы, но **выключены**
  (`ENABLE_STARS_STAKES`, `ENABLE_TON_STAKES`). Прочитайте раздел «Ставки» до включения.

## Команды

| Команда | Где | Что делает |
|---|---|---|
| `/cduel @user [50 stars \| 0.5 ton]` | группа | вызвать игрока (или ответить `/cduel` на его сообщение) |
| `/ccancel` | везде | отменить свою дуэль, пока раунд не начался |
| `/cstats [@user]` | везде | рейтинг, место, победы/поражения, лучшая и средняя реакция, серия побед |
| `/ctop` | везде | табло дуэлянтов (из группы приходит в личку) |
| `/chelp` (в личке и `/help`) | везде | правила |
| `/terms`, `/paysupport` | везде | условия, поддержка по платежам (стандартные имена, их требует Telegram) |

Под итогом дуэли в группе есть кнопка **🔁 Реванш**: любой из двух участников одним нажатием вызывает
соперника снова, с той же ставкой.

## Рейтинг

* Эло, старт 1000, коэффициент `ELO_K` (32). Победа над более сильным даёт больше очков; ничья между
  равными — ±0. Отменённые дуэли рейтинг не трогают.
* Изменение показывается в группе («📈 @a 1016 (+16) · @b 984 (−16)») и крупно на экране итога в виджете.
* Табло сортируется по рейтингу; в нём все, кто сыграл хотя бы одну дуэль.
* В «лучшую» и «среднюю» реакцию идут только честные замеры (обычная победа/поражение и ничья по времени):
  фальстарты и «быстрее человека» не считаются.
* Серия побед: с трёх подряд бот отмечает её в итоге.

## Как это работает

```
/cduel @user  ──►  эфемерное приглашение только вызванному (Принять / Отказаться)
Принять      ──►  виджет дуэли уходит каждому игроку в личку (sendWidget, chat_data = состояние)
виджет       ──►  фоновый запрос "hi" (игрок на месте) и "ack:<n>" (замер пинга)
сервер       ──►  случайная пауза 2–6 с → editMessageWidgetData(chat_data = «go») обоим
игрок        ──►  тап → request("p") → widget_query; время фиксирует сервер
судья        ──►  результат → editMessageWidgetData обоим + сообщение в исходной группе + табло
```

### Античит
* Время сигнала и время нажатия — серверные (`time.monotonic()` в момент отправки сигнала и в момент получения
  апдейта). Клиент не передаёт и не может передать времена.
* Сигнал решает только сервер: клиент не знает паузу заранее.
* Пинг: перед раундом бот шлёт каждому игроку `ack`-запрос и меряет круг «правка chat_data → ответ виджета».
  Реакция = `(приход нажатия − момент сигнала) − RTT`. RTT берётся медианой и ограничен сверху `MAX_RTT_MS`,
  чтобы его нельзя было раздуть. Нет замера — `DEFAULT_RTT_MS`.
* Реакция быстрее `MIN_HUMAN_MS` (по умолчанию 80 мс) после поправки считается нажатием до сигнала.
* Разница не больше `TIE_MS` (20 мс) — ничья.
* Первое нарушение не решает дуэль мгновенно: короткое окно (0,3 с) на случай, если нарушил и второй (тогда ничья).

**Честно об ограничениях:** виджет исполняется в песочнице Telegram и не может быть изменён игроком, но
сетевой уровень (искусственная задержка ответа на пинг, автоматизация через клиентский API) эта схема не
закрывает полностью. `RTT` ограничен, `MIN_HUMAN_MS` отсекает сверхчеловеческую реакцию; для серьёзных
ставок нужны дополнительные меры (история реакций, ручной разбор).

### Таймауты
| Что | Параметр | По умолчанию |
|---|---|---|
| Вызов не принят | `CHALLENGE_TTL` | 5 мин |
| Не внесена ставка | `STAKE_TTL` | 3 мин |
| Игрок не открыл виджет / не готов | `READY_TTL` | 90 с |
| Игрок не нажал после сигнала | `RESPONSE_TIMEOUT` | 5 с |
| Повторный вызов игрока, который отказал | `CHALLENGE_COOLDOWN` | 60 с |

Если после сигнала нажал только один игрок, по умолчанию дуэль **отменяется** (`ONE_SIDED_POLICY=cancel`);
`ONE_SIDED_POLICY=win` отдаёт победу нажавшему. Отменённые дуэли не меняют рейтинг, ставки возвращаются.

## Создание бота

1. В [@BotFather](https://t.me/BotFather): `/newbot`, имя и username (должен заканчиваться на `bot`). Сохраните токен.
2. Для приватных вызовов в группе **сделайте бота администратором группы**. Документация Bot API 10.4: эфемерное
   сообщение любому участнику, а не только нажавшему кнопку, бот может отправить только как администратор
   (см. «Ephemeral Messages and Commands»). Без этого `/cduel` ответит подсказкой, а вызов будет отменён.
3. Чтобы бот видел username игроков, которые ещё ни разу ему не писали, отключите privacy mode
   (`/setprivacy` → Disable) или пусть игроки хоть раз напишут боту. Бот находит соперника по `@username`
   среди тех, кого уже видел, либо по ответу командой на его сообщение, либо по упоминанию с профилем.
4. **Каждый игрок должен нажать Start у бота** — виджеты уходят в личку. Если не нажал, бот в группе даст кнопку
   с deep-link.
5. Команды бот регистрирует сам (`setMyCommands`); `/cduel` объявляется эфемерной (`EPHEMERAL_COMMANDS=true`),
   поэтому текст команды остальным в чате не виден.
6. Платежи Stars отдельного провайдера не требуют. Документация Telegram требует, чтобы бот отвечал на `/terms`
   и `/paysupport` — они есть, **замените тексты** в `duelbot/texts.py` на свои.

## Запуск

```bash
cd telegram-duel-bot
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env        # впишите BOT_TOKEN
python -m duelbot
```

Тесты: `pytest` (124 теста, ~17 с), линтер: `ruff check .`. Проверка JS виджетов в настоящем Chromium с
заглушкой `TelegramWidget`: `node tools/widget_check.js [папка для скриншотов]` (нужен Playwright; это не
песочница Telegram, а быстрая проверка логики и вёрстки). Всё это гоняет GitHub Actions
(`.github/workflows/duelbot.yml`) на каждый push в `telegram-duel-bot/`.

Настройки проверяются при старте: например, `DELAY_MIN > DELAY_MAX` или `TON_NETWORK=1` не дадут боту
запуститься с непонятной ошибкой позже.

### Docker

```bash
docker build -t duelbot .
docker run -d --name duelbot --restart unless-stopped --env-file .env -v duelbot-data:/data duelbot
```

База лежит в томе `/data` (`DB_PATH=/data/duelbot.db`). Обновление схемы при новой версии происходит само
при старте: недостающие колонки добавляются, данные сохраняются.

## Важное про окружения

В продакшене (Bot API 10.4) виджеты работают **только в личных чатах**: нет виджетов в группах, inline и пересылки.
Поэтому дуэль идёт в личке, а итог бот публикует в группе обычным сообщением. `/ctop` из группы присылает
табло в личку. Всё остальное работает на **тестовом сервере**; для него `USE_TEST_SERVER=true`, а
`WIDGETS_IN_GROUPS=true` отправит табло прямо в группу.

Тестовый сервер Telegram полностью отделён от основного: нужен отдельный аккаунт и отдельный бот у @BotFather.
Вход (по документации Telegram): iOS — 10 раз тапнуть иконку Settings → Accounts → Login to another account → Test;
Telegram Desktop — ☰ Settings → Shift + Alt + правый клик по «Add Account» → «Test Server»; macOS — 10 кликов по
Settings, затем ⌘ + клик по «Add Account». Запросы идут на `https://api.telegram.org/bot<token>/test/METHOD`
(это делает `USE_TEST_SERVER=true`).

## Как проверить вдвоём

Нужны два аккаунта (можно один с телефона, второй с десктопа) и бот-админ в тестовой группе.

1. Оба написали боту `/start` в личке.
2. В группе первый: `/cduel @username_второго`. Второй увидит приватное приглашение с кнопками; первый получит
   приватное подтверждение. Другие участники группы не видят ни команду, ни приглашение.
3. Второй нажимает «🤠 Принять». В личке у обоих появляется виджет: «Ждём соперника…» → пинг → «Приготовься…» →
   красный экран «ЖМИ!».
4. Проверьте сценарии: честная победа; нажатие до красного экрана (фальстарт); не нажимать вовсе (отмена через 5 с);
   не принимать вызов 5 минут (вызов истекает); закрыть чат с ботом до начала (таймаут готовности).
5. Итог придёт в группу; `/ctop` покажет «Табло дуэлянтов» (shared widget), оно обновляется после каждой дуэли
   через `editSharedWidgetData` (не чаще раза в секунду). С `USE_TEST_SERVER=true` и `WIDGETS_IN_GROUPS=true`
   табло можно отправить в группу, а виджет с `watchPublicData()` обновится на экране сам.
6. Ставки (по желанию, **сначала тестовый сервер**): `/cduel @user 5 stars` или `/cduel @user 0.1 ton`.

## Ставки (Stars и TON)

Реализованы за интерфейсом `StakeProvider` (`duelbot/stakes/`). Включаются флагами в `.env`. Это деньги, поэтому
читайте до включения.

> Ставки на реакцию это азартная игра в ряде юрисдикций, а правила Telegram для Stars и ботов могут ограничивать
> такой сценарий. Условия для разработчиков я в этой сессии прочитать не смог (страница недоступна), поэтому
> **это не проверено**. Ответственность за законность и соблюдение правил Telegram на владельце бота.

### Stars (`ENABLE_STARS_STAKES=true`)
Bot API **не умеет отправлять Stars пользователю**: есть `sendInvoice`, `refundStarPayment` (возврат плательщику) и
`sendGift`. Поэтому:
* оба игрока заранее платят ставку счётом (`currency=XTR`); раунд начинается после обеих оплат;
* победитель получает **свою ставку обратно** (`refundStarPayment`); ставка проигравшего остаётся на балансе бота;
* опционально `STARS_WINNER_GIFT_ID` — бот дарит победителю подарок (`sendGift`) за счёт своего баланса;
* ничья, отмена, таймаут, сбой — возврат обоим; неудавшиеся возвраты повторяются раз в минуту;
* `telegram_payment_charge_id` хранится в `star_payments`, повторная доставка платежа игнорируется.

### TON (`ENABLE_TON_STAKES=true`)
Бот **не хранит ключи и не подписывает переводы**. Схема «проигравший платит победителю напрямую»:
1. В виджете каждый игрок подтверждает ставку (`request('join', {wallet:true})`); бот получает `TonWalletCard`
   (адрес и баланс) и проверяет, что хватает на ставку и комиссию (`TON_FEE_RESERVE`).
2. После победы создаётся долг. Проигравший жмёт «Заплатить» в виджете: бот отвечает готовой транзакцией
   (адрес победителя, сумма, комментарий `duel:<id>`), виджет открывает кошелёк (`wallet.sendTransaction`).
3. Оплату подтверждает **бот сам по цепочке**: ищет во входящих транзакциях адреса победителя (toncenter API v3
   `GET /transactions`) перевод от кошелька проигравшего с нужной суммой и комментарием, не `aborted`,
   не `bounced`, не `emulated`, с `mc_block_seqno`. Проверка по `msg_hash`, о которой сообщает кошелёк,
   не используется как доказательство платежа: документация TON прямо не рекомендует отслеживание внешнего сообщения
   для обработки платежей.
4. Это **не эскроу**. Проигравший может не заплатить: по истечении `TON_CLAIM_TTL` долг помечается `unpaid`,
   игрок блокируется для TON-ставок, пока не оплатит (запоздалая оплата снимает блок).
5. Сеть: `TON_NETWORK=-239` (mainnet) или `-3` (testnet); `TON_API_BASE` должен указывать на индексатор той же сети.
   Без `TON_API_KEY` toncenter ограничивает 1 запрос в секунду (по документации), клиент это учитывает.

## Структура

```
duelbot/
  engine/       чистая логика без Telegram: judge (судья), timing (пинг, задержка), rating, states, settlement
  storage/      aiosqlite: игроки, дуэли, платежи Stars, долги TON
  widgets/      duel.html, leaderboard.html (самодостаточные, без CDN), payloads.py, render.py (проверка лимитов)
  stakes/       StakeProvider: base (интерфейс + NoStake), stars, ton (+ ton_utils, ton_client)
  services/     duel_service (оркестрация раунда), leaderboard_service
  handlers/     команды, кнопки, платежи, перехват widget_query; parsing.py
  bot_api_raw.py  методы Bot API 10.4 поверх aiohttp
tests/          pytest: engine, storage, TON, виджеты, сквозные сценарии с эмуляцией сети, aiogram-роутер
tools/widget_check.js  проверка виджетов в Chromium
```
